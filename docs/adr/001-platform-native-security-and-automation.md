# ADR 001: 플랫폼 네이티브 보안 저장소와 자동화 API 사용

- 상태: 승인 (일부 대체됨)
- 날짜: 2026-08-13
- 후속: macOS 저장소를 "데이터 보호 키체인"으로 정한 부분은
  [ADR 002](002-macos-file-based-keychain.md)가 대체합니다. 나머지 결정은 유효합니다.

## 배경

Windows와 macOS에서 사용 흐름은 같지만 비밀번호 보안 저장소, 데스크톱 UI, 접근성 자동화,
코드 서명과 배포 체계가 서로 다릅니다. 하나의 크로스 플랫폼 UI 런타임을 추가하면 배포 크기와
권한 처리가 복잡해지며 각 운영체제 보안 API를 우회하는 별도 계층이 필요합니다.

## 결정

- Windows는 C#/.NET, DPAPI `CurrentUser`, Windows UI Automation과 네이티브 입력 API를
  사용합니다.
- macOS는 SwiftUI, 데이터 보호 키체인, Accessibility와 Core Graphics 이벤트 API를
  사용합니다.
- 두 앱 모두 카카오톡 설치 경로와 실행 프로세스, 로그인 UI, 포커스 대상을 확인하고 검증이
  실패하면 입력을 중단합니다.
- 비밀번호는 클립보드, 평문 파일, 원격 서버를 거치지 않습니다.

## 결과

- 운영체제별 보안·서명 모범 경로를 직접 사용할 수 있고 런타임 의존성을 줄입니다.
- Windows와 macOS 코드는 별도로 빌드하고 카카오톡 UI 변경에 맞춰 각각 유지해야 합니다.
- macOS 소스는 Windows에서 작성할 수 있지만 최종 컴파일, 권한, 서명, 공증, 실제 카카오톡
  연동 검증은 Mac이 필요합니다.
